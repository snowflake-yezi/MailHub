# MailHub UI 灵动化改造设计文档

> 状态：Phase 0–4 已实现；本文保留为设计与验收记录 | 最后校准：2026-07-11

> 本文的视觉/交互改造已落地到 React SPA。后续优化以 `ui-second-optimization-phase-plan.md` 为准。

---

## 1. 背景

当前 React SPA 管理端已经覆盖仪表盘、服务器、过滤规则、邮箱、邮件查询、系统配置等核心功能，但视觉和交互仍停留在早期后台模板状态：

- 左侧深色导航、白卡片、灰表格的组合比较普通，和 MailHub 图标的灵动感不匹配。
- 页面大量依赖表格和内联样式，信息层级弱，用户需要用力扫读。
- 状态、动作、危险操作没有统一的视觉语义，健康、降级、回收、清理、热加载等状态缺少“第一眼可判断”的表现。
- 现有导航文案和部分页面存在中文编码异常风险，需要在 UI 改造时一并清理。
- 系统配置页已经参考过「早柚核心」的插件管理模式，但这种模块化体验尚未扩展到全站。

本次先产出设计文档，不直接改代码。后续实现以此文档为准逐步落地。

## 2. 参考对象

### 2.1 早柚核心：模块化控制台

项目内既有 `dynamic-config-design.md` 已记录早柚核心配置界面特征：

- 左侧导航按功能模块分类。
- 主区域以“模块名称 / 是否启用 / 参数配置”的表格或列表组织模块。
- 每个模块有明确启用开关和配置入口。
- 参数配置通过 Modal 或抽屉进入，集中编辑该模块参数。
- 底部或顶部保留保存、重载、重启提示。

对 MailHub 的启发：

- 将“服务器池、域名池、过滤引擎、转发目标池、生命周期、系统配置”都表达成可启停、可观测、可进入配置的模块。
- 页面不只是 CRUD，而是“模块运行状态 + 关键参数 + 下一步操作”。
- 配置、开关、热加载、重启生效等操作需要统一组件。

### 2.2 NapCatQQ：现代、轻量、品牌化

公开 NapCatQQ 官网呈现为 VitePress 风格：顶部简洁导航、品牌图标、浅/深色主题切换、快速开始/GitHub 入口、特性卡片、生态与工具分区。项目定位为现代化协议端框架，强调轻量、开箱即用、适配快速。

对 MailHub 的启发：

- 保持信息干净，减少重装饰，让品牌色、图标和状态组件承担记忆点。
- 提供明确的“快速动作”：注册节点、创建邮箱、查询邮件、重载配置、查看异常。
- 用轻盈的浅色主界面 + 可选深色模式替代厚重深色侧栏。
- 顶部导航和侧边导航都要有品牌标识，MailHub 图标应成为第一屏信号。

### 2.3 MailHub 自身品牌资产

仓库根目录已有 `MailHub.png`，内容是蓝色系二次元邮箱形象，带 `@`、信封、环形符号。它适合承担：

- 登录页主视觉。
- 侧边栏/顶栏品牌头像。
- 仪表盘欢迎区和空状态插画。
- favicon / PWA icon / 桌面快捷图标来源。

注意：主后台是运维工具，不应被插画淹没。图标应作为“品牌点睛”，主体仍保持高效、克制、可扫读。

## 3. 设计目标

### 3.1 产品目标

1. 让管理端看起来像 MailHub，而不是任意后台模板。
2. 让运维人员能更快判断系统健康、节点负载、邮箱增长、异常邮件和配置生效状态。
3. 让高频操作更短路径完成：创建邮箱、注册服务器、切换转发目标、查询邮件、重载配置。
4. 统一交互模式，减少每个页面自己写按钮、弹窗、提示、表格样式。

### 3.2 视觉目标

1. 灵动但不花哨：蓝色品牌主线 + 清爽背景 + 适量柔和高亮。
2. 管理后台优先：信息密度高、布局稳定、状态可扫读。
3. 避免单一蓝色铺满全站：用蓝、青、薄荷绿、珊瑚红、琥珀黄构成状态与强调色。
4. 支持浅色优先，预留深色模式。

### 3.3 工程目标

1. 先建立设计 token 和通用组件，再改页面。
2. 尽量不引入大型 UI 框架，保持当前 React + Vite 简洁依赖。
3. 可引入 `lucide-react` 作为统一图标库，替代 emoji 和乱码风险。
4. 消除页面内联样式，沉淀为可复用 CSS 类。

## 4. 信息架构

### 4.1 新导航结构

建议将左侧导航从“功能列表”改成“运行视角 + 管理视角”：

| 分组 | 页面 | 路由 | 说明 |
|------|------|------|------|
| 总览 | 仪表盘 | `/` | 健康、负载、今日创建、异常入口 |
| 资源 | 服务器池 | `/servers` | 节点、域名绑定、心跳、探测 |
| 资源 | 邮箱账户 | `/mailboxes` | 创建、批量导入、回收站、恢复/清理 |
| 资源 | 邮件查询 | `/emails` | 邮箱维度检索、正文预览、附件下载 |
| 策略 | 过滤规则 | `/filters` | pass / flag / block 规则 |
| 策略 | 转发目标 | 可并入邮箱页或新增 `/integrations` | 集成邮箱池、当前 active 目标 |
| 系统 | 系统配置 | `/config` | 模块化参数、热加载、重启提示 |

### 4.2 页面顶栏

每个页面顶部统一为：

- 左侧：页面标题 + 一句话上下文。
- 中部或右侧：全局搜索入口（邮箱地址 / Message-ID / 服务器名）。
- 右侧：主题切换、刷新、当前管理员、退出。

### 4.3 快速动作

仪表盘和各页面顶部保留高频动作：

- 创建邮箱
- 批量创建
- 注册服务器
- 查询邮件
- 通知节点重载
- 查看回收站

按钮使用图标 + 短文案；危险操作统一红色轮廓或红色实心确认。

## 5. 视觉系统

### 5.1 设计关键词

- 轻盈：大面积浅背景、低噪声边框、柔和阴影。
- 灵动：状态点、微动效、图标、轻微色彩过渡。
- 精准：表格密度、数值对齐、操作位置稳定。
- 品牌化：MailHub 图标、蓝色主色、信封和节点意象。

### 5.2 色彩 token

| Token | 建议值 | 用途 |
|------|--------|------|
| `--color-brand` | `#2388ff` | 主按钮、导航 active、链接 |
| `--color-brand-strong` | `#1167d8` | hover / active |
| `--color-brand-soft` | `#e8f3ff` | active 背景、浅提示 |
| `--color-bg` | `#f6f8fb` | 页面背景 |
| `--color-surface` | `#ffffff` | 面板、卡片、弹窗 |
| `--color-surface-alt` | `#f9fbff` | 表格头、浅分区 |
| `--color-text` | `#172033` | 主文字 |
| `--color-muted` | `#65758b` | 次级文字 |
| `--color-border` | `#dfe7f2` | 边框 |
| `--color-success` | `#19a974` | healthy / active |
| `--color-warning` | `#f5a524` | degraded / 需重启 |
| `--color-danger` | `#e5484d` | down / delete / purge |
| `--color-info` | `#28a9e0` | draining / loading |

避免让页面被单一蓝色淹没：主色只用于导航、关键按钮和局部高亮；状态色按语义分担。

### 5.3 主题偏好与自定义配色

当前设计要求已覆盖浅色优先、深色模式和固定语义色 token；第二次优化补充“用户可自定义主题颜色偏好”：

- 主题模式：继续支持浅色 / 深色切换，并持久化到本地偏好。
- 品牌色：允许管理员选择 `--color-brand`，系统自动派生 `--color-brand-strong` / `--color-brand-soft`，避免手工维护一整套色阶。
- 预设色板：内置 MailHub Blue、Mint、Cyan、Coral 等少量可读预设，不提供过多装饰性主题。
- 自定义输入：支持色板选择 + `#RRGGBB` 输入，非法颜色不保存。
- 语义色边界：success / warning / danger / info 默认保持系统语义色，仅可在后续“高级外观”中修改，避免状态含义被品牌色污染。
- 持久化策略：优先落浏览器 `localStorage`；若后续需要全局部署默认值，再接入 mgmt `system_configs`。
- 重置：提供“恢复 MailHub 默认配色”。

验收：

- 切换品牌色后，导航 active、主按钮、链接、进度强调色同步变化。
- 浅色/深色下自定义品牌色仍满足可读性；不合格颜色需要提示或回退。
- 状态 Badge 的红/黄/绿/蓝语义不被品牌色覆盖。

### 5.4 字体与尺寸

- 字体：系统 UI 字体，保留中文清晰度。
- 页面标题：24px / 700。
- 区块标题：16px / 650。
- 表格文字：13px。
- 表单文字：14px。
- 行高：1.45 到 1.6。
- 禁止使用随视口缩放的字体。

### 5.5 圆角与阴影

- 卡片、面板、Modal：8px。
- 按钮、输入框、标签：6px。
- 图标按钮：8px，固定 34px 或 36px。
- 阴影克制：`0 8px 24px rgba(21, 42, 75, 0.08)` 只用于浮层；普通面板主要靠边框。

### 5.6 图标

引入 `lucide-react` 后建议映射：

| 页面/动作 | 图标 |
|-----------|------|
| 仪表盘 | `LayoutDashboard` |
| 服务器 | `Server` |
| 邮箱 | `Inbox` / `Mail` |
| 邮件查询 | `Search` |
| 过滤规则 | `SlidersHorizontal` / `Filter` |
| 系统配置 | `Settings` |
| 创建 | `Plus` |
| 编辑 | `Pencil` |
| 删除 | `Trash2` |
| 恢复 | `RotateCcw` |
| 下载 | `Download` |
| 重载 | `RefreshCw` |
| 主题 | `Sun` / `Moon` |
| 状态 | `CircleCheck` / `TriangleAlert` / `CircleX` |

## 6. 布局方案

### 6.1 Shell

推荐布局：

- 左侧导航：展开态 260px，折叠态 72px，浅色半透明面板，顶部显示 MailHub 图标 + 名称。
- 侧栏顶部提供展开/收起按钮，展开态显示导航图标 + 文案 + 徽标，折叠态只显示图标，鼠标悬停显示 tooltip。
- 顶部栏：固定在主区域顶部，包含面包屑、全局搜索、主题/刷新/账户操作。
- 主内容：最大宽度不强制限制，后台页面应充分利用宽屏。
- 移动端：侧栏折叠为抽屉，顶部显示品牌和菜单按钮。

侧栏状态建议保存在 `localStorage`：

- 首次访问默认展开，方便理解系统结构。
- 用户手动收起后保持收起，刷新页面不跳动。
- 小于 900px 时忽略桌面展开状态，使用移动端抽屉。

### 6.2 导航状态

导航项包含：

- 统一图标。
- 中文标题。
- 可选徽标，例如异常节点数量、回收站数量。
- active 背景使用 `--color-brand-soft`，文字 `--color-brand-strong`。
- 折叠态 active 通过图标底色和左侧细指示条表达，不显示文字。
- 折叠态需要给每个导航图标增加 `title` 或自定义 tooltip，避免只剩图标后难以辨认。

### 6.3 空状态

空状态使用 MailHub 图标的轻量版本：

- 无服务器：提示注册第一个 mail-node。
- 无邮箱：提示创建邮箱或导入 CSV。
- 无邮件：提示输入邮箱地址查询。
- 无配置项：提示检查数据库初始化。

空状态不写大段说明，只给一句原因和一个主要动作。

## 7. 组件规范

### 7.1 AppShell

统一承载：

- Sidebar
- Topbar
- PageHeader
- ToastProvider
- ConfirmDialog
- ThemeProvider

现状 `ConfigPage` 内部重复渲染 `app-layout` 和 `Sidebar`，需要改为只在 `Layout.jsx` 提供整体壳层。

Sidebar 需要支持：

- `expanded / collapsed` 两种桌面状态。
- 桌面状态持久化到 `localStorage`。
- 移动端抽屉开关。
- 折叠态 tooltip。
- 折叠/展开动画只改变宽度和文字透明度，避免主内容剧烈抖动。

### 7.2 PageHeader

属性：

- `title`
- `description`
- `actions`
- `meta`

示例：

```jsx
<PageHeader
  title="服务器池"
  description="管理 mail-node 节点、域名绑定、心跳与主动探测"
  actions={<Button icon={Plus}>注册服务器</Button>}
/>
```

### 7.3 MetricCard

用于仪表盘和模块概览：

- 标题
- 主数值
- 趋势/副文本
- 图标
- 状态色

避免纯大数字白卡片，加入小型状态点或微型进度条。

### 7.4 StatusBadge

统一状态映射：

| 状态 | 文案 | 样式 |
|------|------|------|
| `healthy` | 健康 | green |
| `degraded` | 降级 | amber |
| `draining` | 缩容中 | blue |
| `down` | 离线 | red |
| `active` | 生效中 | green |
| `soft_deleted` | 回收站 | amber |
| `purged` | 已清理 | gray |
| `reloadable` | 热加载 | blue |
| `restart_required` | 需重启 | amber |

### 7.5 DataTable

统一表格能力：

- 顶部工具栏：搜索、筛选、批量操作、刷新。
- 表头 sticky 可选。
- 行 hover 高亮。
- 操作列固定宽度，按钮位置稳定。
- 空状态和 loading 状态统一。
- 小屏时变成列表卡片，不横向挤爆。

### 7.6 ModulePanel

借鉴早柚核心的模块管理模式，用于系统配置和未来策略模块：

- 左侧：模块名称、描述、影响范围。
- 中间：启用开关、参数数量、热加载数量。
- 右侧：配置、重载、查看日志。

### 7.7 Drawer / Modal

- 表单编辑优先用 Drawer，避免打断上下文。
- 危险确认用 Modal。
- 邮件详情保留双栏或三栏布局，避免详情弹窗遮挡列表。

## 8. 页面改造方案

### 8.1 登录页

目标：第一眼看到 MailHub 品牌。

布局：

- 左侧或顶部使用 `MailHub.png` 作为品牌插画。
- 登录表单放在独立面板中。
- 背景使用浅蓝到白的柔和层次，不使用重渐变和装饰圆球。
- 表单包含账号、密码、登录按钮、错误提示。

### 8.2 仪表盘

目标：从“统计卡片 + 表格”改成运维总控台。

模块：

- 顶部欢迎区：MailHub 图标、系统健康摘要、当前时间、快速动作。
- 健康概览：健康节点/总节点、活跃邮箱、今日创建、异常节点。
- 节点负载：进度条展示各服务器负载。
- 待处理事项：down 节点、degraded 节点、需重启配置、回收站待清理。
- 最近活动：创建邮箱、删除/恢复、配置重载、节点状态变化。

### 8.3 服务器池

目标：让节点状态和域名归属一眼可见。

改造：

- 顶部统计：健康、降级、缩容、离线。
- 表格列：名称、API、关联域名、负载、状态、最近心跳、最近探测、失败次数、操作。
- 负载用进度条替代纯文本。
- 状态变更使用分段动作：缩容 / 恢复。
- 编辑服务器使用 Drawer。
- 删除服务器使用危险确认 Modal。

### 8.4 邮箱账户

目标：增强批量运维效率。

改造：

- 顶部 tabs：全部 / 正常 / 回收站 / 已清理。
- 工具栏：按域名、服务器、状态筛选。
- 创建邮箱用 Drawer；批量创建用独立步骤式 Modal。
- 回收站操作明确区分：恢复、永久清理。
- 密码修改放入行内操作菜单。

### 8.5 邮件查询

目标：变成轻量邮件审阅器。

布局：

- 左侧搜索和邮件列表。
- 右侧邮件详情。
- 详情顶部显示主题、发件人、收件人、时间、解析状态。
- 正文 tabs：Text / HTML / Raw 元信息。
- 附件以文件条目展示，带下载图标、文件类型、大小、inline 标记。

体验：

- 搜索框固定在列表顶部。
- 列表项不用传统表格，改为邮件摘要卡片/紧凑列表。
- HTML 预览仍使用安全 iframe。

### 8.6 过滤规则

目标：策略语义清楚。

改造：

- 按 action 分组或筛选：pass / flag / block。
- 规则列表显示匹配条件、动作、启用状态、命中统计（若后端未来支持）。
- 新建/编辑使用 Drawer。
- 动作颜色固定：pass green、flag amber、block red。

### 8.7 系统配置

目标：把早柚核心模块化配置体验做扎实。

改造：

- 页面主体从表格改为 ModulePanel 列表或 2 列网格。
- 每个模块展示：启用状态、参数数、热加载数、需重启数、影响组件。
- “参数配置”打开 Drawer，左侧为参数分类，右侧为表单。
- 修改后出现未保存状态条。
- 顶部保留“通知节点重载”。
- 非热加载项保存后显示“需重启”提示。

- 将根目录 `MailHub.png` 复制到 `mgmt-system/web/public/mailhub.png`。
